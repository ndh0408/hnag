# Mapbox + Location — build setup (HNAG Flutter)

The Dart side is already wired:
- `lib/main.dart` → `MapboxOptions.setAccessToken(...)` (public `pk.` token baked in, override with `--dart-define=MAPBOX_TOKEN=pk.…`).
- `lib/api/location_service.dart` → device location with HCM fallback.
- `lib/screens/nearby_restaurants_screen.dart` → "Bản đồ" button opens `FoodMapScreen` with real pins from `/v1/restaurants/nearby` (now returns `lat`/`lng`).
- `pubspec.yaml` → `mapbox_maps_flutter: ^2.6.0`, `geolocator: ^13.0.1`.

What remains is **native build config** + a **secret download token**. Do this once on whatever holds the native folders (`android/`, `ios/Runner`) — they are generated by `flutter create`, so if missing run `flutter create --platforms=android,ios .` in `code/flutter` first.

---

## 1. Create the secret download token (REQUIRED to build)

Mapbox's native SDKs download from a private repo that needs a **secret** token (different from the public `pk.` token already in the app):

1. mapbox.com → Account → Tokens → **Create a token**
2. Name: `hnag-downloads`
3. Under **Secret scopes**, tick **`DOWNLOADS:READ`**  ← the only special scope needed
4. Create → copy the token (starts with **`sk.`**, shown only once)

---

## 2. Android

**`~/.gradle/gradle.properties`** (build machine / CI — NOT committed):
```properties
MAPBOX_DOWNLOADS_TOKEN=sk.eyJ1...   # the sk. token from step 1
```

**`android/build.gradle`** → `allprojects { repositories { ... } }` add:
```groovy
maven {
    url 'https://api.mapbox.com/downloads/v2/releases/maven'
    authentication { basic(BasicAuthentication) }
    credentials {
        username = 'mapbox'
        password = providers.gradleProperty('MAPBOX_DOWNLOADS_TOKEN').get()
    }
}
```

**`android/app/build.gradle`** → ensure `minSdkVersion 21` (Mapbox v11 needs ≥21).

**`android/app/src/main/AndroidManifest.xml`** → inside `<manifest>`:
```xml
<uses-permission android:name="android.permission.ACCESS_FINE_LOCATION"/>
<uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION"/>
```

**CI (`.github/workflows/mobile-ci.yml`):** add repo secret `MAPBOX_DOWNLOADS_TOKEN`, then before `flutter build appbundle` add:
```yaml
      - run: echo "MAPBOX_DOWNLOADS_TOKEN=${{ secrets.MAPBOX_DOWNLOADS_TOKEN }}" >> ~/.gradle/gradle.properties
```

---

## 3. iOS

**`~/.netrc`** (the VM `vm` / CI mac — NOT committed):
```
machine api.mapbox.com
  login mapbox
  password sk.eyJ1...   # the sk. token from step 1
```

**`ios/Runner/Info.plist`** → add:
```xml
<key>NSLocationWhenInUseUsageDescription</key>
<string>HNAG dùng vị trí để gợi ý quán ăn gần bạn.</string>
```

**`ios/Podfile`** → `platform :ios, '13.0'` (Mapbox v11 needs ≥12; 13 is safe).

The iOS build runs on the macOS VM (`vm`) via Fastlane / `setup-on-vm.sh` — add the `.netrc` there once.

---

## 4. Build

```bash
cd code/flutter
flutter pub get
flutter build appbundle --release      # Android (CI does this)
flutter build ipa --release            # iOS (on the VM; signing per HNAG iOS notes)
# Map token override (optional, instead of the baked-in pk.):
#   flutter build ... --dart-define=MAPBOX_TOKEN=pk.xxxx
```

## Notes
- The public `pk.` token is safe to ship in the binary (Mapbox public tokens are designed for client use). Rotate in the dashboard if abused.
- The secret `sk.` token must NEVER be committed — it lives only in `~/.gradle/gradle.properties` / `~/.netrc` / CI secrets.
- This stripped repo copy has no `android/`; CI/build must `flutter create` (or check out the full repo) before applying the above.
